# 안전 연구실 구현 계획

작성: 2026-10-03. 대상: 컴퓨터공학 진학을 희망하는 고2 학생의 탐구용 웹 프로토타입.

## 탐구 질문

화재·구조물·대원의 시계열을 설명 가능한 알고리즘으로 처리하고, 판단의 근거와 한계를 함께 보여주면 지휘 정보의 이해를 도울 수 있는가?

## 선행연구에서 가져올 설계

- 「특수재난현장 진압대원의 안전을 위한 통합 지휘시스템에 관한 연구」(2015), 103~105쪽, 그림 6~7: 관성센서와 기준 위치를 이용한 실내 측위, 환경·개인·위치 정보 통합, 조건별 경보. 논문의 실험은 주로 무선 전송에 대한 것으로 위치 정확도를 입증했다고 해석하지 않는다.
- 「소방대원 진압작전의 의사결정을 위한 붕괴예측시스템 개발」(2017 연차보고서), 본문 25~34쪽(PDF 35~44쪽): 변위·고유진동수·감쇠비의 변화, PCA 기반 특성 융합, 구조해석과 임계치 연계. 본문 30쪽의 -2.75는 가정값이고 모든 건물에 적용되는 임계치가 아니다. 이번 구현은 공개 데이터에 실제로 있는 처짐과 변화율을 이용하는 축소 실험이다.

## 데이터 선정 및 적합성 확인

1. NIST P-Flash, DOI 10.18434/M32258: 공개 CData 시뮬레이션 1,000개. 실제 화재 관측으로 표시하지 않는다. 온도 채널·시간 단위·사건 기준을 원본에서 확인한 뒤 단기 선형 추세 모델과 온도 기준선을 비교한다.
2. NIST Localized Fire Test Steel Beam, DOI 10.18434/mds2-1856: 강재 보 실제 가열·재하 실험의 온도·변위. 실험별 기준 구간과 후속 구간을 나누고 처짐/변화율 이상을 탐지한다. 건물 전체 붕괴 확률로 확대하지 않는다.
3. Fu, Hanyuan, Pedestrian inertial navigation dataset with wearable sensor, DOI 10.57745/ZCBIIB: 가속도·자이로·자기장·기압 및 참조 궤적. 보행 PDR과 참조 궤적을 비교한다. 소방관의 기어가기·고온·금속 환경 성능은 미검증이다.

원본은 data/research/raw, 파생 자료는 data/research/processed에 저장한다. 다운로드 스크립트와 SHA-256, 원본 URL, 라이선스, 선택한 실험·채널, 변환 규칙을 남긴다. 접근 불가하거나 부적합한 후보는 근거를 남기고 대체한다.

## 모듈 구조

### 데이터 접근 확인 후 확정 (구현 전 변경)

P-Flash 원본/영구 식별자 경로가 반복적으로 시간 초과되어, 다운로드와 재현이 가능한 공식 firemodels/exp의 UL_NIST_Vents Test 1~4로 교체한다. 실제 실험의 열전대에서 산출한 고온층 온도 `T_upper`(°C), `Time`(s)을 쓴다. 600°C 도달을 교육용 대리지표로 정의하며 실제 플래시오버 판정 정답으로 부르지 않는다. 표본 4건으로 기계학습 성능을 주장하지 않고, 고정된 과거 60초 선형 추세/60초 전망과 현재 온도 기준을 비교한다. Test 1은 개발 확인, Test 2~4는 분리 평가한다. 원본은 Git commit ae8a6fca191222d2c047903bdcf61fb49bfb3f41로 고정한다.

보행 원본은 저장소가 제공하는 묶음 다운로드 API로 확보했고, 내부 파일을 제공자의 MD5와 대조한다. Test 02에서 보폭만 보정하고 Test 03·04에서 평가한다. 각 궤적의 초기 방향 설정에 처음 10초 기준 궤적을 이용하는 제약을 공개하며, 그 이후 구간만 오차를 평가한다. 실제 UWB 관측은 없으므로 UWB는 별도 원리·합성 기하 예제로 검증하고 실측 정확도에 포함하지 않는다.

- scripts/fetch_research_data.py: 고정된 공식 출처의 파일 다운로드 및 무결성 기록.
- scripts/prepare_research_data.py: 데이터 정제, 시간·단위 확인, 실험 단위 분할, 검증 결과 산출.
- app/services/research_algorithms.py: 과거와 현재만 사용하는 순수 알고리즘 함수.
- app/research_api.py: 준비된 실험과 검증 결과를 제공하는 API. 기존 LSTM 입력 형식과 독립적.
- app/static/research.html, research.js, research.css: 세 실험의 재생·차트·근거·데이터 카드. 기존 홈페이지에서 접근.

## 구현 순서와 완료 조건

1. 두 PDF의 관련 본문·그림을 읽고 데이터 필드를 확인한다.
2. 원본을 다운로드하고 공개 이용 조건과 출처를 기록한다.
3. 플래시오버 기준 접근 추론, PDR, 구조 변형 감지를 각각 구현한다.
4. 실험 단위 검증으로 오탐·놓침·오차·리드타임을 계산한다. 결과가 좋지 않아도 그대로 표시한다. 참조 정답은 추론 입력에 사용하지 않는다(초기 좌표/방향 등 설정이 필요한 경우 명시).
5. 세 실험을 한 연구실에 통합하되 시간과 공간이 다른 데이터임을 명시한다. 재생/일시정지/구간 탐색, 설명 펼치기, 데이터 다운로드를 제공한다.
6. 유효성 검사, 누락·비정상 입력, 미래 데이터 누출 방지, API, 기존 기능, 화면 반응형·키보드 접근을 검증한다.
7. 구현 결과와 센서 프로토타입 구상, 간단한 HCI 검토, 학생이 직접 수행할 후속 실험을 문서화한다.

## 판단과 화면의 원칙

- 결과는 자료 유형(실측/공개 시뮬레이션/가정), 시간, 단위, 판정 근거와 함께 표시한다.
- 독립 실험들의 점수를 평균 내어 통합 안전 확률을 만들지 않는다.
- 측정 불가·예측 불가·검증되지 않은 조건은 명시한다. 데이터 누락을 안전으로 바꾸지 않는다.
- 하드웨어는 상온 모형·실내 보행으로만 시연한다. 소방 현장 인증 장비로 주장하지 않는다.
