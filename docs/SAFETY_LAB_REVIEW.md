# 센서 근거 기반 위험 징후 통합 모니터링

2026-10-03 구현. 고2 컴퓨터공학 탐구를 위한 설명 가능한 프로토타입이다.
연구 질문은 **“센서의 현재값만 볼 때와 시간에 따른 변화를 볼 때, 무엇을 더 알아낼 수 있고 어디서 실패하는가?”**이다.

## 무엇을 만들었나

기존 FastAPI/웹사이트에 `/research`를 연결했다. 환경·대원·구조물의 센서 데이터를
`원본 → 품질 확인 → 모듈별 알고리즘 → 근거·오차·경보 이력`이라는 같은 흐름으로 처리한다.
각 데이터는 시간·장소가 다른 실험이므로 하나의 현장 지도나 종합 안전 확률로 합치지 않는다.
학생이 데이터 선택, 수학적 가정, 알고리즘 비교, 웹 HCI를 설명할 수 있는 구조다.

실제 공개 원본을 내려받았고 임의의 센서 곡선을 만들어 실측으로 표시하지 않았다.
UWB의 세 거리 입력만 **합성 기하 예제**이며 실측 위치 성능과 분리했다.
현재 실행 경로는 저장 데이터 재생이다. 센서 하드웨어 조립·새 실시간 수집·현장 검증은 수행하지 않았다.

## 선행연구를 반영한 부분

| 선행연구 | 반영 | 그대로 사용하지 않은 부분 |
|---|---|---|
| 「특수재난현장 진압대원의 안전을 위한 통합 지휘시스템에 관한 연구」(2015), 본문 103–105쪽 | 환경·개인·위치 정보 통합, 관성센서와 기준 위치 결합, 조건별 알림 | 논문 실험은 주로 RF 통신이다. 이를 위치 정확도 검증으로 인용하지 않았다. |
| 「소방대원 진압작전의 의사결정을 위한 붕괴예측시스템 개발」(2017 연차보고서), 본문 25–34쪽/PDF 35–44쪽 | 변위·진동수·감쇠 변화에 근거한 구조 이상 탐지 관점, 기준값의 구조별 보정 필요성 | 본문 30쪽 −2.75는 가정값이다. 보편적 붕괴 임계값으로 쓰지 않았고 PCA/진동수 분석을 구현했다고 주장하지 않았다. |

사용자가 제공한 두 PDF 원본은 변경하지 않았다. 제공 PDF의 설계를 축소하여 공개 데이터에 실제로 존재하는 신호부터 검증했다.

## 데이터와 알고리즘

### 1. 플래시오버 징후: 고온층 600°C 도달의 대리 과제

[공식 firemodels/exp UL_NIST_Vents](https://github.com/firemodels/exp/tree/ae8a6fca191222d2c047903bdcf61fb49bfb3f41/UL_NIST_Vents)의 실제 화재 실험 4건을 사용했다.
[FDS 실험 설명](https://github.com/firemodels/fds/blob/master/Manuals/FDS_Validation_Guide/Experiment_Chapter.tex)의 UL/NIST Vent Experiments에 따르면
2012년 자연가스 버너와 천장 환기구를 조절한 6.1×4.3×2.4 m 구획 실험이다.
`Time`은 초, `T_upper`는 열전대 배열로부터 산출한 고온층 온도(°C)이다.
개별 열전대 최대 온도를 고온층 평균처럼 쓰지 않았다. Test 1의 비수치/빈 값 17개는 결측으로 유지한다.

현재 온도에 최근 60초 선형 회귀 기울기의 양수 부분 × 60초를 더한다.
전망 ≥ 600°C이면 추가 확인, 현재값 ≥ 600°C이면 기준 도달, 완전한 창/값이 없으면 판단 자료 부족이다.
600°C는 [P-Flash 연구](https://www.nist.gov/publications/p-flash-machine-learning-based-model-flashover-prediction-using-recovered-temperature)의
고온층 온도 기준을 참고한 **대리지표**다. 이 데이터에는 실제 플래시오버 발생 라벨이 없으므로 실제 플래시오버 정확도는 알 수 없다.
기존 LSTM 피해등급의 확률과도 다른 출력이다.

초기 계획의 [P-Flash 공개 시뮬레이션](https://doi.org/10.18434/M32258)은 원본 다운로드 경로가 반복해서 시간 초과되어
재현 가능한 UL/NIST 실험으로 교체했다. NIST P-Flash 모델이나 감지기 고장 후 온도 복원 기능을 재현한 것은 아니다.

Test 1은 개발 확인, Test 2–4는 분리 평가다. 학습형 분류기 없이 창 60초/전망 60초를 고정했으며,
현재값 400°C 규칙을 단순 비교 기준으로 두었다. 모든 평가는 첫 600°C 도달 전,
향후 60초가 완전히 존재하고 결측이 없는 시점만 포함한다.

| Test 2–4 합계 | 도달 전 60초 구간 탐지 | 미탐 | 기준 미도달 구간 오탐 | 진음성 |
|---|---:|---:|---:|---:|
| 60초 추세 전망 | 2 | 2 | 3 | 568 |
| 현재값 400°C | 2 | 2 | 34 | 537 |

Test 4의 기준 도달은 3,480초, 도달 직전 유효 경보의 최대 선행 시간은 30초였다.
그러나 이 실험 초반에도 추세 경보가 한 번 잘못 발생했다. “첫 경보부터 30초 후 발생”이라는 뜻은 아니다.
양성 실험은 1건이고 60초 구간들은 서로 겹친다. 수백 개 구간을 독립 실험으로 세거나 보편적 정확도/우월성으로 해석하지 않는다.

### 2. 위치: 가속도 걸음 감지 + 자이로 방향 적분

[Fu, Hanyuan, Pedestrian inertial navigation dataset with wearable sensor](https://doi.org/10.57745/ZCBIIB)를 사용했다.
원본 6개 궤적을 포함한 27 MB 압축파일을 확보하고 제공자 MD5와 확인했다.
TEST 02(보폭 보정), TEST 03(같은 참가자의 다른 궤적), TEST 04(다른 참가자)를 선택했다.
기준은 발 부착 INS로 산출한 추정 궤적이다. 측량 정답이나 화재 현장 소방대원 데이터가 아니다.

가속도 크기에서 초기 중력을 제거 → 과거값만 사용하는 저역 통과 필터 → 봉우리 1.0 m/s²와 0.28초 최소 간격으로 걸음 감지 →
자이로 z축 회전량 적분 → 보폭만큼 좌표 갱신한다. 회전 단위는 rad/s, 가속도는 m/s²로 해석한다.
수평으로 든 장치 조건의 단순 모델이며 완전한 3차원 자세 필터는 아니다.
자기장 값과 보정 파일의 단위 매칭이 명확하지 않아 자력계 융합은 제외했다.

타임스탬프는 GPS tow + nano×10⁻⁹로 복원하고, 중복을 제거한 후 가속도 시점보다 과거인 가장 최근 자이로 표본을 결합한다.
센서 매칭 실패나 100 ms 이상 간격은 조용히 보간하지 않고 데이터 준비를 중단한다.
처음 40초 정지 구간에서 바이어스를 구한다. TEST 02 기준 경로의 1 Hz 이동거리로 보폭을 보정하고 나머지 실험에 고정한다.
각 실험의 초기 방향은 처음 10초 기준 이동으로 맞췄고 그 구간은 화면상 보정 중이며 평가에서 제외한다.
실제 기기로 바꿀 때는 이 초기 정보를 출입구 좌표/알려진 방향/UWB로 제공해야 한다.
그 이후 기준 궤적은 오차 산출에만 사용한다. 평가지표는 0.5초 간격에 시간 동기화한 수평 거리다.

| 분리 평가 | 평균 오차 | 95백분위 오차 | 종료 지점 오차 |
|---|---:|---:|---:|
| TEST 03, 사무실·계단 포함 | 10.46 m | 24.41 m | 28.12 m |
| TEST 04, 다른 참가자·야외 숲길 | 16.27 m | 44.91 m | 46.73 m |

오차가 커서 관성 추정만으로 정확한 현장 위치를 제시하기 어렵다는 결과다.
다음 단계는 UWB 거리/기준점으로 오차가 얼마나 줄어드는지 비교하는 것이다.
이번에 구현한 `/api/v1/research/uwb`는 3개 이상 앵커의 거리로 2차원 최소제곱 삼변측량을 수행한다.
음수 거리·일직선/나쁜 앵커 배치는 거절하고 잔차 RMS를 보여준다. 잔차는 위치 오차 보장값이 아니다.
실측 UWB 융합 성능은 검증하지 않았다.

### 3. 붕괴 관련: 실제 강재 보의 변형 이상 감지

[NIST Localized Fire Tests of Steel Beams](https://doi.org/10.18434/mds2-1856)의 원본 Excel(약 12.6 MB)을 사용했다.
Test 7–9에서 시간, VD1 수직 변위(mm), tc17 보 온도(°C)를 읽었다. 빈 끝행만 제거하고 시간 순서를 검증했다.
보 온도는 판정 입력이 아니라 참고 정보로 표시한다.

Test 7 초기 60초를 참조 구간으로 사용해 절대 변위와 20초 회귀 기울기 각각의
`중앙값 + 6 × 1.4826 × MAD`를 계산한다. 3 mm, 0.5 mm/min의 하한은 시연용 설계값이다.
이 기준을 Test 8–9에 고정 적용하고 두 기준이 함께 5초 지속되면 변형 이상 경보를 기록한다.
경보는 유지하되 센서값이 없으면 현재 판단은 자료 부족으로 전환한다.

Test 9는 큰 변형에서 결합 경보가 발생하지만 Test 8은 결합 경보가 발생하지 않는다.
이 미감지 가능성도 UI에 표시한다. 초기 60초가 보편적 건강 상태라는 근거는 없고,
온도·하중·지지조건이 다른 건물로 기준을 옮길 수 없다. 공개 파일에는 일관된 붕괴 시점 라벨과
비붕괴 대조군이 없어서 붕괴 정확도와 붕괴 전 리드타임은 **평가 불가**다.
원문에서 제안한 진동수/PCA는 새로 가속도 시계열과 파손 실험을 확보한 뒤 별도 검증해야 한다.

## 하드웨어를 붙이는 최소 구상

| 노드 | 센서/원리 | 학생 수준 시연 | 다음에 검증할 것 |
|---|---|---|---|
| 환경 | 다점 열전대 → 온도 변환 → 시간 추세 | 실제 화재 원본 재생, 상온 센서로 통신만 확인 | 센서 위치·고온층 산출·응답 지연·누락 |
| 대원 | IMU 관성 보행 + UWB 앵커 3개 이상 거리 | 복도 보행, 알려진 좌표에서 초기화 | 같은 경로 5회, 보행/포복 구분, PDR 대 UWB 보정 |
| 구조 | 변위 센서 + IMU, 보의 변형/진동 변화 | 상온 탄성 모형 보에 작은 하중 | 센서 장착·노이즈·구조별 기준, 변위와 진동 결합 |

ESP32 같은 수집 노드 → 시각 동기화 → JSON 패킷 → 서버 품질 확인 → 알고리즘 → 웹의 흐름으로 연결한다.
제안 패킷은 node_id, timestamp, sequence, unit, quality, battery와 센서값을 포함한다.
품질 분기는 결측/범위 초과/역전된 시각/통신 지연을 먼저 확인한다. 새 패킷이 3초 없으면
정상으로 남기지 않고 통신 끊김을 표시하는 설계다. 이 스트리밍 기능은 아직 구현 범위 밖이다.
고온·화재·실제 붕괴 실험 대신 상온 모형과 공개 원본을 조합해 프로토타입을 시연한다.

## HCI 검토와 반영

| 검토 항목 | 반영한 내용 | 확인/남은 일 |
|---|---|---|
| 현재 상태 파악 | 판단·근거·센서 수치·단위·재생 시각을 한 화면에 배치 | 데스크톱 화면 확인 |
| 오해 방지 | 실측/대리지표/합성 예제, 현재 추정/사후 평가 구분 | ‘안전’이나 근거 없는 확률 표현 제외 |
| 사용자의 제어 | 재생·정지·속도·탐색·주요 구간 이동 | 실제 브라우저 동작 확인 |
| 색상 의존 완화 | 상태마다 문구와 기호를 함께 표시 | 키보드 이동·레이블 확인 |
| 정보량 | 모듈 선택 + 접을 수 있는 원리/센서 구성 | 모바일 390 px에서 가로 넘침 없이 확인 |
| 재현·신뢰 | 출처·이용 조건·체크섬·원본/분석 CSV 다운로드 | 브라우저 CSV 다운로드 확인 |

사용성 평가는 아직 실제 학생/소방관 참여 실험이 아니다. 학생 3–5명에게
“기준 도달 시점 찾기 / 결측과 정상 구분 / 오탐 설명 / CSV 내려받기”를 수행하게 하고,
과제 성공률·소요시간·혼동 문장을 기록하면 다음 HCI 결과를 만들 수 있다.

## 재현과 학생이 이어갈 탐구

`scripts/fetch_research_data.py` → `scripts/prepare_research_data.py` → `app/research_api.py` → 웹 순서다.
알고리즘은 `app/services/research_algorithms.py`에 분리했고 파생 JSON/CSV는 `data/research/processed`에 보관했다.
원본·SHA-256·출처는 `data/research/sources.json`에 기록한다. 단위·분할·임계값은 각 실험 JSON에 있다.

자동 검증은 기존 기능 포함 16개 테스트, 실제 Edge에서 모듈 전환·재생·정지·키보드 탐색·CSV·UWB 계산·모바일 넘침·JS 오류를 확인했다.
미래 자료 비참조, 결측 처리, 구조 경보 지속조건, UWB 퇴화 기하, 누락 데이터의 API 오류도 검증한다.

학생의 후속 실험은 (1) 전망 창 30/60/90초를 개발 실험에서만 선택하고 별도 실험에서 오탐/미탐 비교,
(2) 고정 보폭과 개인 보정 보폭 비교, (3) PDR와 UWB 보정의 오차 비교,
(4) 구조 기준의 3/6/9 MAD 민감도와 미감지 비교가 적합하다.
새 결과에 맞춰 가설·실패 원인·개선·검증 기록을 남겨야 탐구 과정이 드러난다.
완성된 사이트나 높은 정확도 주장만으로 학생의 연구 기여를 대신하지 않는다.
