# 화재 현장 브리핑 UI의 HCI 설계

## 1. 설계 목표

사용자는 화재 현장에서 짧은 시간 안에 상황을 파악해야 하는 소방관이다. 보호장비,
소음, 긴장, 이동, 여러 보고가 겹치는 환경에서는 탐색과 조작 자체가 부담이 된다.
따라서 이 화면은 기능 수를 늘리는 대신 다음 한 가지 과업에 집중한다.

> 피해 수준과 센서 변화를 확인하고, 지금 먼저 확인할 행동을 찾는다.

설계 과정은 사용 맥락과 과업을 먼저 정의하고 결과를 반복 평가하는 인간 중심 설계의
관점을 따른다. 참고 기준은
[ISO 9241-210:2019](https://www.iso.org/standard/77520.html)와
[WCAG 2.2](https://www.w3.org/TR/wcag/)이다.

## 2. 사용자와 사용 맥락

- **주 사용자**: 현장 지휘관과 출동 대원
- **환경**: 소음, 연기, 낮은 시인성, 장갑 착용, 불안정한 통신, 높은 시간 압박
- **목표**: 피해등급 확인, 센서 변화 탐지, 우선 행동 확인, 건물 핵심정보 확인
- **실패 위험**: 핵심 정보 탐색 지연, 수치 오독, 중요 행동 누락, 기술 설명과 현장 사실의 혼동

이 분석에 따라 화면 조작을 없애고 자동 갱신 방식을 사용했다. 사용자가 메뉴를 찾거나
모드를 선택하지 않아도 핵심 정보가 같은 위치에 나타난다.

## 3. 과업 분석과 정보 순서

첫 화면의 읽기 순서는 실제 판단 순서와 일치시켰다.

1. **피해등급과 신뢰도**로 전체 위험 수준을 파악한다.
2. **현장 요약**으로 센서와 분석 결과를 한 문장 흐름으로 읽는다.
3. **최근 30초 센서**에서 현재값과 상승·하강 방향을 확인한다.
4. **위험 징후·즉시 행동**에서 현재 수치에 연결된 행동 세 가지만 확인한다.
5. **대상 건물**에서 구조, 용도, 층수, 사용 상태를 확인한다.

확률표, 개발 기술명, 전체 데이터, 설정, 반복 설명은 이 흐름에 직접 필요하지 않아
화면에서 제외했다.

## 4. 적용한 HCI 원칙

### 인지 부하 최소화

- 한 화면에 하나의 상황과 상위 행동 세 개만 제공한다.
- 장문 설명과 같은 의미의 반복 문구를 제거했다.
- 기술 구현명 대신 `피해등급`, `현장 요약`, `즉시 확인`처럼 업무 용어를 사용한다.
- 조작 메뉴를 없애 선택에 필요한 판단과 손동작을 줄였다.

### 시각적 계층과 게슈탈트 원칙

- 피해등급 숫자를 가장 크고 강한 형태로 표시한다.
- 서로 관련된 등급과 신뢰도, 센서명과 센서값을 근접 배치했다.
- 같은 종류의 센서는 동일한 크기와 구조로 반복해 비교를 빠르게 한다.
- 얇은 경계선과 제한된 색만 사용해 그룹은 구분하되 장식적 시각 요소는 줄였다.

### 기억보다 인식

- 현재값과 최근 30초 변화량을 함께 보여 이전 수치를 기억할 필요가 없다.
- 변화는 `↑`, `↓`, `→` 기호와 부호가 있는 수치로 표시한다.
- 행동 항목은 사용자가 절차를 떠올리는 대신 바로 읽고 확인할 수 있게 한다.
- 화재거동 항목은 `현재 근거 수치 → 관찰할 징후 → 즉시 행동` 순서로 제시한다.

### 색상에 의존하지 않는 표현

- 피해 수준은 색뿐 아니라 등급 숫자와 명칭으로 표시한다.
- 변화 방향은 색과 함께 화살표·부호·수치로 표시한다.
- 우선순위는 강조색과 `즉시·우선·참고` 텍스트를 함께 사용한다.

이는 정보를 색만으로 전달하지 않도록 요구하는 WCAG 2.2의 색상 사용 원칙을
반영한 것이다.

### 일관성과 예측 가능성

- 모든 센서 블록은 `이름 → 현재값 → 변화` 순서를 사용한다.
- 모든 행동 블록은 `우선순위 → 위험명과 현재 근거 → 짧은 실행 내용` 순서를 사용한다.
- 자동 갱신 후에도 영역 위치와 읽기 순서는 바뀌지 않는다.

### 피드백과 오류 복구

- 최초 분석 중에는 짧은 진행 상태만 표시하며 화면 입력을 요구하지 않는다.
- 분석 요청이 실패하면 기존 결과를 지우지 않고 오류 영역만 표시한다.
- 실제 센서 스냅샷이 들어오면 같은 화면 구조 안에서 자동으로 최신 결과로 전환한다.

### 접근성

- 문서 언어, 페이지 제목, 제목 계층, 정의 목록 등 의미 있는 HTML 구조를 사용한다.
- 반복 영역을 건너뛸 수 있는 본문 바로가기 링크를 제공한다.
- 등급, 브리핑, 행동 목록 갱신은 `aria-live`로 보조기기에 전달한다.
- 키보드 초점은 굵은 윤곽선으로 표시하고, 사용자 환경의 동작 줄이기 설정을 존중한다.
- 화면 폭이 좁아져도 등급과 요약을 가능한 한 같은 줄에 유지하고, 센서는 두 열로
  재배치해 핵심 정보가 먼저 보이도록 한다.

## 5. 구현 추적성

- **빠른 위험 인지** → 큰 등급 숫자, 신뢰도 바로 옆 배치
- **변화 탐지** → 최근 30초 기준과 화살표·변화량 병기
- **행동 선택 단순화** → 우선순위 정렬 후 상위 세 개만 노출
- **추상적 경고 방지** → 백드래프트·플래시오버를 단정하지 않고 현재 센서 변화와 현장 관찰 징후를 연결
- **현장 시의성** → 출동 대상의 등록용도·층수·지하층과 최근 30초 센서 추세를 한 행동 문장 안에서 결합
- **장소별 우선순위** → 공동주택 등 재실 가능 용도는 재실자·대피 확인을 상위 세 항목 안에 배치
- **정보 출처 혼동 감소** → 기술명과 개발 상태 문구를 화면에서 제외
- **현장 조작 부담 감소** → 설정·모드 전환 없이 자동 갱신
- **일관된 탐색** → 등급, 요약, 센서, 행동, 건물 순서 고정
- **보조기기 지원** → 제목 구조, 바로가기 링크, 실시간 영역 알림

## 6. 사용성 평가 계획

실제 배포 전 소방 업무 경험자 또는 소방안전 교육 참여자를 대상으로 이전 화면과
개선 화면을 비교한다. 참가자에게 다음 과업을 순서대로 제시한다.

1. 피해등급과 신뢰도를 말한다.
2. 가장 크게 상승한 센서를 찾는다.
3. 가장 먼저 확인할 행동을 말한다.
4. 대상 건물의 지상·지하 층수를 말한다.

측정 항목은 과업 완료 시간, 정답률, 첫 시선이 머무른 영역, 되돌아 읽은 횟수,
주관적 정신적 부담이다. 목표 기준은 다음과 같다.

- 피해등급 확인: 3초 이내, 정답률 95% 이상
- 센서 변화 확인: 5초 이내, 정답률 90% 이상
- 첫 행동 확인: 7초 이내, 정답률 90% 이상
- 건물 층수 확인: 5초 이내, 정답률 90% 이상

과업 후에는 간단한 인터뷰와 NASA-TLX 방식의 정신적 부담 질문을 사용해 수치만으로
드러나지 않는 혼동 원인을 수집한다. 결과에 따라 문구 길이, 글자 크기, 영역 순서를
반복 개선한다.

## 7. 학생 탐구 관점

이 프로젝트의 HCI 탐구는 단순히 화면을 예쁘게 만드는 작업이 아니다. 사용자와
환경을 분석하고, 정보량과 조작 수를 줄인 뒤, 과업 시간과 오류율로 개선 효과를
검증하는 과정이다. 생기부에는 다음 탐구 흐름으로 정리할 수 있다.

> 고스트레스 화재 현장의 사용자 맥락을 분석하고, 인지 부하와 시각적 계층 원칙을
> 적용해 브리핑 UI를 단순화하였다. 이후 과업 완료 시간과 정답률을 기준으로 사용성을
> 평가하고 반복 개선하는 인간 중심 설계 과정을 수행하였다.
